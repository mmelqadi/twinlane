# Metadata-preserving start candidate

SOURCE ONLY. This candidate is not installed and supplies no admission, cleanup, replay or business authority. The installed runtime remains6088b8d. A later named installation and actual implementation-start scope must approve the exact reviewed packet and its effects.

Proposed public option: `twinlane run --preserve-existing-metadata ...`. Initial support was Claude only. Candidate v3 (below) adds a Codex start that runs ONLY an explicitly supplied, qualified standalone `TWINLANE_CODEX_BIN`; every other Codex path (PATH or app discovery, app-owned or shared private copies, leases, prunes) and every cross-engine failover is still refused before any binary-cache effect. Even a fresh BOTH-account meter read for a Claude task can acquire/prune Codex binaries: this mode therefore reads only the existing ordinary TTL-qualified meter cache, with original recorded timestamps and recalculated ages. It never refreshes a token or writes a meter cache. Missing/expired cache refuses; queued preflight and receipt threads inherit the same rule. This does not manufacture a fresh observation. Included-subscription routing, freshness and money guards remain required. No paid override or API fallback is added.

## Protected job artifacts

The guarantee covers pre-existing JOB ARTIFACTS, not every file on the computer. Standard start skips the global age-based `runner.env.json` sweep. Admission, global slot scans, waits, continuation checks and threaded receipt overlap scans observe other jobs' `child-starting` files without deleting them. Stable recorded PID/creation-stamp DEAD evidence is logically nonblocking while the marker remains on disk. ALIVE, UNKNOWN, malformed/unreadable identity or changed marker bytes remains blocking. Reads around an observation do not prove an atomic snapshot or eliminate an ABA race; writer-directory and slot serialization still apply, and the real claimant checks current evidence.

Preserving mode requires real PID/stamp integers, bounded runner.pid parsing and exact decimal FILETIME values. It refuses any existing writer reservation, even a DEAD one, rather than replace that protected record. Existing runner locks are not reclaimed. A terminal preserving job is not replayed. Fresh allocation uses exclusive directory creation; collisions never replace an old folder. Normal new-job runner release compares PID AND creation stamp. No original-token equivalence is fabricated.

The mode is opt-in, persists in the new job spec, binds to coordination caller intent/fingerprint and is independently required by the detached runner argv. An expected preserving runner refuses removed/malformed/disagreeing mode before claiming. Child dispatch inherits its actual parent's preserving setting before a sweep. Legacy absent-mode fingerprints and ordinary behavior remain unchanged. This is not a new authentication adapter or a cryptographic signature: trusted job/spec/argv confinement remains necessary.

## Handoff security tradeoff

120 seconds is the existing SWEEP threshold, not a consumption TTL. `claim_and_read` has no age check. Skipping the sweep retains old sensitive handoffs longer; their existing owner-only ACL is unchanged. The candidate does not revive/consume an old handoff, change expiry semantics, weaken arbitration or claim that age proves safety. New-job handoff consumption retains the existing single-winner decision and creation-stamp binding. A separate explicit security/design decision would be needed for any expiry/retention policy change.

## Candidate v3: qualified explicit standalone Codex

SOURCE ONLY, from base 738f12b; not installed. V3 does not drop the v1/v2 Codex guards. It narrows them: a preserving start may run Codex only through ONE explicitly supplied standalone binary.

Qualification (`common.qualify_explicit_codex_bin`): `TWINLANE_CODEX_BIN` must be set to an absolute local drive path, without padding, control, quoting, wildcard or stream characters. Network/device paths are refused before any filesystem access. The value must name a regular file with exactly one hard link, reached without any symlink, junction or short name (its canonical path equals its normalized path). Its canonical location must be exactly `%LOCALAPPDATA%/Programs/OpenAI/Codex/bin/codex.exe`; arbitrary executables elsewhere remain unsupported. It must also lie outside every protected root: the desktop app's `bin/` and `.plugin-appserver` folders, `%LOCALAPPDATA%\OpenAI`, the Codex home, `%ProgramFiles%\WindowsApps` and twinlane's shared `bin/` store. The recorded identity is path, size, mtime_ns, file index, volume and SHA-256. Hashing runs only after the path checks, and a file that changes while it is hashed is refused. Nothing is discovered, copied, leased, pruned, version-cached or executed by qualification.

Continuity: `plan_run` records the identity in the new job spec (`codex_binary`) and forces `failover` off. Explicit `--failover` and a `TWINLANE_CODEX_RUN` adapter are refused, because an adapter cannot verify the hand-off. `preflight` refuses any engine other than the job's primary, so neither Claude to Codex nor Codex to Claude happens. Then, before any meter read, it re-qualifies the current `TWINLANE_CODEX_BIN` and requires an exact match with the recorded identity. `_run_codex` never calls `acquire_codex_binary`. It requires the built-in runner argv from `build_argv`, re-qualifies again, and repeats the check after a `min_cli_version` probe if one is configured. It sets an independent `--preserve-existing-metadata` runner argument (recorded in the actual attempt argv) and hands the runner `TWINLANE_CODEX_BIN` plus `TWINLANE_CODEX_BIN_QUALIFIED` (the identity JSON). The built-in runner re-checks stat identity and SHA-256 right before `Popen`. Preserving mode requires the hand-off even if both environment values disappear. On any mismatch, missing binary, absent or malformed hand-off it exits 3 (`refused`) without falling back to `codex` on PATH. An ordinary start drops any stray hand-off variable and acquires its binary exactly as before. A detached runner receives the caller's environment through the existing owner-only env hand-off and the identity through its own `job.json`; both must still agree at launch.

Unchanged: the TTL-qualified cached meter with per-section freshness downgrade, the route decision, `codex_credit_refusal` (unknown, stale, paid credits) and every writer/slot/UNKNOWN predicate. A preserving Codex receipt takes token counts from the job's own exec events or runner total, never from session rollouts.

Remaining risk: the runner's final check and the OS process start are not atomic. A same-user process that can rewrite the file in that window is outside this guard, because the file is outside twinlane's custody by design. Any link or short-name indirection is refused, even to an unprotected target, and a user whose path legitimately crosses a junction must give the final path. A configured `min_cli_version` still executes `binary --version`, the existing guard, unchanged. Owned spans: `twinlane/jobs.py` (plan/preflight/launch/token paths), `twinlane/common.py` (qualification only), `twinlane/codex_runner.py` (hand-off check only), `tests/test_preserving_codex_start.py`, hermetic env set-up in `tests/test_preserving_start.py`, and this note. The separate restart-drill source planner is described in `RESTART-DRILL-PLAN.md`; no source acceptance is physical restart proof.
